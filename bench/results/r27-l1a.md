## The drafter plans from a CPU upper bound

[L1a-draft-ub-plan.diff](../../patches-v0310/L1a-draft-ub-plan.diff) changes `vllm/v1/attention/backends/flashinfer.py` and `vllm/v1/worker/gpu/spec_decode/autoregressive/speculator.py`. With `VLLM_SM12X_DRAFT_UB_PLAN=1`, the speculator tags its own `FlashInferMetadataBuilder` instances. A tagged builder uses `seq_lens_cpu_upper_bound` in place of the blocking `seq_lens.cpu()` device-to-host copy for pure draft decode (`max_query_len == 1`), when the upper bound exists and neither cascade attention nor decode context parallelism is active. Other builds keep the A_S path; the target builders are never tagged. Unset or any flag value other than `1` leaves the layer inactive.

FlashInfer stages each plan in a page-locked host buffer reused by the next plan on that wrapper. L1a records a CUDA event after each draft build and waits for that event before the next draft build, inside `gpu_sync_allowed()`, so the previous plan's asynchronous staging copies finish before the host buffer is overwritten. The event orders the staging copies rather than graph completion, allowing CPU planning to overlap the preceding draft graph's replay. Graph capture records and waits on no such events.

The bound can let draft attention read positions beyond the request's exact draft length after rejections. KV writes still use the exact GPU slot mappings, and target verification and rejection sampling are unchanged. Draft acceptance and greedy near-ties can move; the layer does not make the draft plan exact. No L1a GPU profile was supplied, so this write-up reports no measured D2H count or GPU-idle reduction.
