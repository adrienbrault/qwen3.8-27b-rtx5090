# Patch 0148 — PCIe IPC MTP admission

Offline source audit and delivery, 2026-09-05. Base: `vllm-qwen38:v0290rc2-nvfp4kv-revival-prs-fi0616-pcieipc-bsshash` (supplied `src/` plus 0147). ## Behavior and exact functions changed

- `vllm/envs.py`: add `_sm12x_pcie_ipc_mtp_enabled`, the type declaration and environment getter registration; update `compile_factors` to ignore this runtime dispatch/capture knob. The existing opaque all-reduce operation in the compiled model is unchanged. Registering the knob without this exclusion would change even the unset compile key and split the paired arms.
- `vllm/distributed/device_communicators/cuda_communicator.py::CudaCommunicator.__init__`: validate the knob before communicator initialization; for a TP group, raise if an explicitly requested MTP PCIe communicator is absent/disabled. The original joint prerequisite exchange still agrees refusals before this error. Invalid settings and failed admission cannot masquerade as a successful CUSTOM comparison.
- `vllm/distributed/device_communicators/pcie_ipc_all_reduce.py::PcieIpcAllReduce._disabled_reason`: extend the existing DFlash exception to normalized `method == "mtp"` only when opted in. Require the draft to be bf16, hidden 5120, TP2, and reject `enable_sp`, `fuse_gemm_comms`, or `fuse_allreduce_rms` compiler passes that can replace the dispatch being measured. All existing device, target, stream/lifecycle and parallelism prerequisites remain.
- `PcieIpcAllReduce.__init__`: retain the exact existing `PCIe IPC all-reduce enabled` log; after successful workspace initialization, emit the MTP proof once per process (`scope="process"`; `logger.py:93-106,127-134` shows that the default local scope would suppress the second local rank).
- `vllm/v1/worker/gpu/spec_decode/autoregressive/speculator.py::AutoRegressiveSpeculator.capture`: inspect both actual manager descriptor sets, reject unsupported rows before either capture, call `prepare_draft` with the configured drafter hidden size and runtime dtype, and wrap each manager's capture separately in `pcie_comm.capture()`. This covers warmups, PIECEWISE/FULL prefill, single-step decode, and the fused multi-step decode alternative.

Unset or `0` retains the old MTP refusal string and original numerical dispatch, tensor allocation and kernels, including DFlash behavior. The added inactive contexts and environment lookup perform no CUDA work. This patch neither changes the serving launcher nor enables itself in the Dockerfile.

## Knob grammar and proof

`VLLM_SM12X_PCIE_IPC_MTP` accepts only the exact strings `0` and `1`; unset means `0`. Empty, whitespace, `true`, `01`, `2`, etc. raise `ValueError`. `1` requires the existing `VLLM_SM12X_PCIE_IPC_AR=1`, normalized speculative method `mtp`, and all prerequisites above; a disabled TP communicator raises `RuntimeError` with the prerequisite details in preceding logs. Turning this knob on for no drafter or DFlash is an unsupported request. Other speculative methods retain the original refusal `only the sequential DFlash drafter is supported`, including when this knob is on. Use identical settings on both ranks.

Grep this exact proof (twice for TP2, once per worker process):

```text
SM12X PCIe IPC: MTP drafter admitted (sequential AutoRegressive drafter, rows<=320)
```

Also require `PCIe IPC all-reduce enabled` and the backend order containing `PCIE_IPC` before `CUSTOM`. The proof records admission, not completion of all captures or a per-collective execution counter. Require a completed boot and confirm kernel dispatch in a profile.

## Item 2: both shape lists, before first capture

`AutoRegressiveSpeculator.init_cudagraph_manager` (`autoregressive/speculator.py:127-148`) constructs prefill with query length `ns+1`, then decode with query length 1 and FULL_DECODE_ONLY (or NONE). `CudaGraphManager._init_candidates` (`gpu/cudagraph_utils.py:188-295`) builds the descriptors from the resolved compilation configuration:

- Let `S = compilation_config.cudagraph_capture_sizes`, `R = scheduler_config.max_num_seqs`, `C = max_cudagraph_capture_size`, and `q = ns+1`. Under FULL_AND_PIECEWISE, prefill PIECEWISE rows are the **token counts in S**. Prefill FULL rows are the distinct `round_up(s,q)` for `s in S`, bounded by `R*q`, `C`, and `round_up(s,q)/q <= R`. They are not request counts.
- Decode FULL rows use query length 1, so they are the distinct `s in S` bounded by both `R` and `C`; descriptor `num_tokens == num_reqs`. There are no PIECEWISE decode graphs. At daily `R=16`, these rows are at most 16. Decode is not captured for ns1.
- For illustration only, with the supplied R185 `fixed_config.py:18-22` list (maximum 320), decode rows are `{1,2,4,8,10,16}`; prefill FULL ns3 rows are `{4,8,12,16,20,24,32,40,48,56,64}`, ns4 rows are `{5,10,20,25,35,40,50,60,65,75,80}`, and prefill PIECEWISE uses that entire 41-size list. Runtime descriptors, rather than this historical illustration, are authoritative.

`SpeculatorCudaGraphManager.capture` (`autoregressive/cudagraph_utils.py:45-64`) feeds descriptor `num_tokens` to its forward function. The new code reads the same `_capture_descs` that base capture consumes (`gpu/cudagraph_utils.py:335-350`), including all modes, not `graphs` (empty before capture). It validates every prefill token count and every decode request count; an invalid one-row-per-request decode descriptor or a row outside 1..320 raises before preparation or either capture. This also validates any future/configured prefill schedule above the cap instead of silently omitting it.

Existing `prepare_draft(hidden,dtype)` (`pcie_ipc_all_reduce.py:163-166`) prepares **every integer 1..MAX_ROWS=320**, a metadata superset that covers both lists in the admitted configuration. Hidden 5120 bf16 fits `MAX_NUMEL=320*5120`; the patch passes `draft_model_config.get_hidden_size()` and `self.dtype` (runtime dtype comes from the target in `spec_decode/speculator.py:103-118`). No new GPU slab/tensor is allocated per prepared shape. There is no reliance on the target's capture list. Workspace preparation still agrees metadata on Gloo, even on repeated calls (`workspace.py:91-115`), and finishes before capture.

Both new wrappers mirror DFlash (`dflash/speculator.py:155-178`). Base manager capture also enters `graph_capture` (`gpu/cudagraph_utils.py:331`), whose existing 0138 context nests safely: `workspace.py:144-169` tracks depth and synchronizes the outer boundaries. Profiling and final capture both use these entry points. Replay remains serialized on the forward stream.

## Eager dummy before capture

The runner invokes dummy propose at `gpu/model_runner.py:780-804`, before `capture_model` at :902. At communicator construction, `pcie_ipc_all_reduce.py:60-62` calls `prepare_for_capture`; :141-149 already registers every target hidden5120 row from 1 through 320. Thus eligible MTP dummy shapes at that same hidden and dtype are normally pre-resolved, as are today's same-hidden DFlash shapes.

If a supported, known-hidden shape is genuinely unresolved **eagerly**, `should_use` does not reject it merely for that miss (`pcie_ipc_all_reduce.py:168-177`); `workspace.py:171-178` calls `prepare` outside capture, then launches. Larger rows, an unknown hidden, unsupported dtype/layout or capacity fail metadata admission and retain the old dispatch chain (`workspace.py:117-126`). During actual CUDA capture an unresolved supported shape returns false at `pcie_ipc_all_reduce.py:174-176`, before any lazy resolution. The supplied implementation therefore does have capture fallback; forcing `workspace.all_reduce` on such a miss would attempt forbidden preparation. This patch preregisters both complete eligible lists rather than depending on that fallback or risking a host collective during capture. Large eager prefill remains on the existing fallback by design; graph schedules above 320 are explicitly refused for this opt-in.

## Item 4: epoch is advanced on the device

**The epoch is device-side; consecutive replays do not bake in a host-selected scratch half. No binding/kernel fix is required for the proposed replay order.** File shorthand here: `.cuh` is `pcie_ipc_ar21/include/flashinfer/comm/pcie_ipc_all_reduce.cuh`; `.cu` is `pcie_ipc_ar21/csrc/bindings.cu`.

- `.cuh:446-469` documents one rank-local call-level epoch/counter pair per scratch region, independent of CTA grid size, with cross-rank agreement coming from identical collective order.
- Device function `advance_scratch_epoch` at `.cuh:540-569` reads persistent device state at :552. After a CTA barrier, the sole CTA or last arriving CTA resets the arrival counter and flips `epoch ^ 1` at :561-566. This happens at **kernel entry**, every execution, including every graph replay. Every CTA has read the old epoch before the flip; the next kernel on the same stream starts only after this launch retires (:503-524).
- The TP2 kernel calls that function at `.cuh:821` and selects scratch using the returned epoch at :822. Its publish/poll/reset protocol uses data sentinels at :832-862. Fixed epoch stride comes from workspace capacity, not current payload length (:2038-2043,2150-2151), so alternating shapes/grids do not change the half boundaries.
- Host launch setup supplies the device `self_signal` state pointer and fixed stride at `.cuh:2161-2168`; `.cu:119-125` obtains the current CUDA stream and launches with PDL false. It has no host epoch increment or capture-time epoch argument. Slab zeroing occurs during allocation, once, at `.cu:39-47`.

Consequently, same-shape repeated decode graphs, fused graphs containing multiple draft forwards, and subsequent target graphs all advance the shared device protocol per collective. Even a graph with an even number of collectives starting its next replay at the same parity has intervening collectives to drain the prior use. This is a source-supported safety conclusion for serialized workspace use and identical collective order on both ranks, not an empirical certification for concurrent streams, rank failure, bad IPC lifetime, signed zeros/NaNs, or debug builds that disable the barriers/epochs (`.cuh:476-500`). The kernel spins without a recovery timeout; the operator's bitwise replay ruler is mandatory.

The brief's “decode graph ns times” is a useful stress scenario but not the exact source count: prefill produces position 0, and the unfused path replays decode **ns-1** times (`autoregressive/speculator.py:492-517`). The fused path replays once (:561-563) with an internal `range(1, ns)` loop (:593-601). Both induce the same sequential collective protocol and are covered by the wrappers.

## Item 5: MTP collectives reach the existing dispatch

Method routing selects `MTPSpeculator`, which loads the draft via `load_eagle_model` (`mtp/speculator.py:12-20`). `models/qwen3_5_mtp.py:118-125` builds the MTP full-attention `Qwen3_5DecoderLayer`. Its attention `o_proj` is `RowParallelLinear` (`models/qwen3_next.py:316-323`, called :456); its dense MLP is the `Qwen2MoeMLP` alias (`qwen3_next.py:54`), whose `down_proj` is also `RowParallelLinear` (`qwen2_moe.py:96-104`, called :115).

Both reduce through `layers/linear.py:1766-1767` -> `distributed/communication_op.py:12-14::tensor_model_parallel_all_reduce` -> `parallel_state.py:713-740::GroupCoordinator.all_reduce/_all_reduce_out_place` -> `device_communicators/cuda_communicator.py:335-337` (the 0138 PCIe branch). The CUDA custom-op path `torch.ops.vllm.all_reduce` at `parallel_state.py:732-733` calls back into the same group dispatcher via :183-188, registered at :383-387. It is not a separate NCCL-only route. During capture that dispatch records the PCIe kernel; subsequent graph replay runs that kernel without Python dispatch.

MTP bf16 embedding reduction also uses this dispatcher (`layers/vocab_parallel_embedding.py:545`); the special FP8/int8 embedding path at :534-542 is outside PCIe's dtype contract. MTP `fc` with `gather_output=True` (`qwen3_5_mtp.py:98-106`) and vocabulary/logits gathers remain all-gathers, outside this all-reduce patch.

The compiler can replace this operation under sequence parallelism or AR fusion (`compilation/passes/pass_manager.py:161-180`); this patch rejects those pass flags for MTP. SM120's ordinary defaults already exclude all-reduce/RMS fusion (`config/vllm.py:177-184`); SP/GEMM communication fusion is disabled when its threshold is absent (:1518-1525). The existing runtime dispatcher still preserves higher-priority backends and metadata fallbacks; the supplied TP2/SM120 bf16 row5120 path is eligible, but a boot proof alone cannot certify every collective. Check a real profile for the MTP kernels and absence of unexpected preempting backends. No custom-op registration, compiled model arithmetic, or all-gather implementation is modified.
