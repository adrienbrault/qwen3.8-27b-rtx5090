## 1. AUDIT

**The served DFlash2 drafter already uses distributed top-k. There is one full-vocabulary collective per ordinary decode step, plus two small candidate collectives.** Do not multiply the target vocabulary payload by the measured 3.1 calls. BSS can affect verification in this source; it is not bypassed for speculative decoding.

All source line references below refer to the unchanged `src/vllm/` dump, before 0143. Shapes assume eight/sixteen live requests, nine draft tokens each, no graph padding, no prompt work. MB means decimal MB. “Input bytes” means the local tensor passed to the collective; for TP2 all-gather this also equals each rank's outgoing remote payload and incoming remote payload, counted separately. The concatenated output is twice that size. Do not add both directions when dividing by a unidirectional full-duplex payload bandwidth.

### Reconciling 3.1

Three logical calls are explained by source: **one large target call + two tiny draft calls**. The evidence gives rounded NCCL **kernel** counts, not phase-tagged collective invocations. `prof_decode_split.py` starts immediately after the last NCCL all-reduce and estimates steps from GDN kernels/48; it does not align to complete engine steps. The final prefill step's logits and draft can therefore enter the numerator without its earlier GDN entering the denominator. One extra three-call tail gives `3*(43+1)/43=3.0698` at c8 and `3*(41+1)/41=3.0732` at c16, both displayed as 3.1, matching the supplied 43/41-step windows. This is a plausible boundary explanation, **not a verified reconstruction**: raw traces are absent. Capture versus eager execution does not intrinsically create a fractional collective count. Mixed prompt-logprob work or a different NCCL kernel decomposition are additional possibilities requiring traces. Ordinary decode logprobs do not explain extra baseline full gathers.

## 2. What BSS changes

`config/parallel.py:167` defines the option; `config/vllm.py:2689` defaults it off and rejects TP1, too few request slots, unlimited max_logprobs, or adaptive verification. The V1 runner lists BSS as unsupported (`config/vllm.py:2654`); use the V2 runner. CUDA + DFlash is supported by V2's selection logic. Qwen3.5 implements both causal-LM and wrapper `compute_logits_local` (`qwen3_5.py:449,617`). Require the boot message `Batch-sharded sampling enabled.`; a model lacking this method emits a disabling warning instead.

`model_runner.py:1411–1477` shards **before** choosing ordinary versus rejection sampling. Whole requests belong to `request_state_index % TP`; all their verification/bonus rows stay together. Each rank projects all owner-sorted rows to its local vocab, skips the logits gather, and `sample/batch_shard.py:302` performs `all_to_all_single`. Balanced TP2 c8 input `[80,124160]` bf16 becomes locally owned `[40,248320]`; c16 becomes `[80,248320]`. Each rank sends half its input to the peer: **9,932,800 / 19,865,600 remote bytes**, half the old all-gather traffic. The tag's input_bytes is still the *whole* input, so halve it for this balanced all-to-all. Owner imbalance changes per-rank send/receive volumes and sampling load; c8 alone does not guarantee balance.

The owner runs grammar masking and the same rejection sampler with the global draft cache indexed by persistent request IDs. It then gathers results:

| New collective, all eager | Balanced local input c8 / c16 | Input/remote bytes c8 / c16 |
|---|---|---:|
| IDs + sampled/rejected counts, `batch_shard.py:637` | `[4,12]` / `[8,12]`, int64 | 384 / 768 |
| Optional IDs/ranks for logprobs, `:558` | `[40,L+1]` / `[80,L+1]`, int64 | `320*(L+1)` / `640*(L+1)` |
| Optional logprob values, `:559` | `[40,L]` / `[80,L]`, fp32 | `160*L` / `320*L` |

Here L=`1+max(num_logprobs,max_token_ids)`; rejection does not return the extra requested token-ID set. NaN tracking adds one packed int64 column, i.e. 32/64 bytes. Padding uses the **maximum** owner request count; replace 4/8 with that count when imbalanced. Output gathers concatenate along rows and then restore original request order. These are not vocabulary-sized under bounded logprob settings. BSS does not change prompt-logprob gathers or the drafter candidate gathers.

**R187 BSS is a real target-verification experiment, not a no-op.** It can roughly halve target communication and sampler work per rank with balanced ownership, but retains vocab-sized all-to-all traffic. Check the enabled boot line and tagged `target_logits_alltoall`; do not judge success by all-gather count alone (three baseline calls become one all-to-all plus three small gathers, before optional logprob gathers).

## 3. DESIGN ONLY — future target sampler

After each rank applies identical, shard-aware logit transformations (grammar, history/penalties for each speculative position, allowed/bad tokens, bias, temperature and min-p in existing order), select local top-k from 124160 columns, gather k fp32 transformed values and k int64 global IDs, and merge to global k with deterministic ties. Mask padding. For k=20 and 80/160 rows, each rank exchanges **19,200 / 38,400 bytes** versus today's 19,865,600 / 39,731,200, about 1035x less. Two separate gathers preserve types; do not encode arbitrary future token IDs in bf16. The existing draft implementation demonstrates the mechanics but does not implement target sampling semantics.

For finite top-k followed by top-p, normalize and apply nucleus filtering over the global top-k in the current order. A fixed small k is **not exact for unrestricted top-p**; arbitrary nucleus support can exceed 2k. Such requests need an exact expanding-support/global-normalization algorithm or an explicitly supported full-gather branch in the eventual design. Threshold ties can retain more than k entries in top-k filtering: reproduce the current tie policy, gather spill ties if required, and never claim equivalence from an arbitrary k-element truncation. Raw logprobs need full-vocab logsumexp/ranks even when sampling support is small; calculate distributed max/sum and rank counts, or use the full-logits implementation for that request. Processed logprobs must honor their requested normalization too.

Greedy: compare transformed local maxima globally, break ties by the lowest global token ID as the existing full-vocab argmax does, and use those IDs for verification and bonus. Keep the same head kernel/output rounding; require exact equality including ties and masked rows. Small communication alone cannot guarantee greedy equality if transformations change.

Stochastic rejection is **not** just sampling from the target candidates and comparing tokens. `rejection_sampler_utils.py` computes p(target token) and q(draft token), accepts with `min(1,p/q)` and draws a replacement from normalized `max(p-q,0)` on first rejection (block mode has its additional acceptance logic). Target finite-k support and DFlash2's 16-candidate q permit sparse evaluation: obtain q on target support, obtain p on the actual proposed token (zero if excluded), preserve each normalization, and form residual weights on target support. Consume the *path-conditioned selector scores* cached by `dflash2/speculator.py:_cache_draft_logits`, not raw unary lm_head candidate values. The existing cache is fp32 dense with -inf outside those 16 candidates. Bonus sampling uses p only. A generic full-support probabilistic drafter requires distributed q normalization and additional values, not the same sparse shortcut. Existing rejection kernels require dense layouts, so this needs a new sparse consumer, not a drop-in tensor substitution.

`sample/gumbel.py:gumbel_noised_argmax` keys noise by seed, source position and token key, with a separate draft salt and fp32/fp64 options. A sharded implementation can use the **global vocab ID** as key on every rank; merged candidate index is wrong. Preserve position, salt, RNG transform, precision and tie resolution, plus rejection's separate acceptance draws. DFlash2's selector walk has its own path sampling; leave it unchanged. Rank consistency is feasible; bitwise identity to the current dense reduction is not established, especially softmax/reduction order and threshold ties. Validate both seeded equality where promised and distribution/acceptance equivalence before promotion.

### Transport estimate and decision

R184 `arbench-bench-214238.json` is an **all-reduce**, not a vocab-all-gather microbench: graph pcie IPC 83,886,080 bytes / 3.281386 ms = 25.564 GB/s, graph rows80/160 = 33.482/65.327 us; NCCL there = 46.011/80.441 us. There are no dedicated all-gather measurements in the supplied r184 files. Use 25.56 GB/s as a transport proxy, not an established NCCL all-gather bandwidth.

At that proxy, target gather payload alone costs **0.777 / 1.554 ms**. Candidate k=20 exchange payload costs 0.000751/0.001502 ms; predicted payload reduction is **0.776 / 1.553 ms/step**. Keep the drafter's existing 11,520/23,040 bytes. Extra tiny-collective launch latency, local top-k, merge, transformations, normalization and sparse rejection subtract from savings. Measured all-gather bucket 1.01/1.99 ms is the absolute bucket ceiling, not a guaranteed gain. A realistic hypothesis remains the R186 50–80% bucket reduction: approximately 0.5–0.8 / 1.0–1.6 ms, pending measurements. Do not add this to BSS's benefit: balanced BSS already removes about 0.389/0.777 ms of the baseline transport; remaining payload headroom versus BSS is about 0.388/0.776 ms. The tagging patch itself promises **zero performance gain** and may add profiling overhead.

### Profiling limitations and measurement plan

NVTX is a host annotation, **not a CUDA graph node**. The individual candidate ranges execute during capture/warmup, not on each replay. They do not automatically attribute replayed NCCL nodes. The existing `evidence/prof_decode_split.py` also ignores all annotations and labels every NCCL non-all-reduce kernel as an all-gather; after BSS that bucket name is wrong for all-to-all. Neither issue can be fixed merely by wrapping collectives.

The companion `prof-vocab-0143.py` reads a torch trace and reports host phase calls, actual local bytes, and NCCL GPU time only when CUDA runtime/driver correlation IDs link a directly launched kernel to a containing host range. It reports **unassigned** kernels (including replay), never assigns them by timestamp proximity, and summarizes the entire supplied trace rather than pretending to reproduce the old decode-window cutoff. No tags is an error. Run inside the container, e.g. `docker exec <container> python3 /mounted/deliver/prof-vocab-0143.py /trace/rank0.pt.trace.json.gz`. Analyze ranks separately; do not sum concurrent rank times.

Use the operator's existing R183 torch-profile recipe and `prof_decode_split.py` for the original gross comparison, plus this companion for target/BSS attribution. For draft node attribution, collect Nsight Systems CUDA+NVTX with graph-node tracing **including startup capture**, correlate graph nodes with capture-time candidate ranges, then follow those nodes on replay. If startup/capture graph mapping is unavailable, a separate eager diagnostic run can verify candidate shapes and owners but does not measure graph-mode timing. The patch deliberately does not force graph fallback or claim replay NVTX works. No Nsight installation/network fetch is part of this deliverable.

Run `evidence/decode_ss.py --help` and the existing operator c8/c16 steady-state protocol for untagged baseline versus untagged BSS, with fixed seeds, ns9, payload lengths, concurrency, acceptance statistics and logprob settings. Take short tagged companion profiles of each arm, retaining both rank traces. First inspect **target logits collective GPU ms/step at c16** and its actual transferred rows/bytes. Expected: baseline one large gather; BSS one half-remote-payload all-to-all, plus result gathers, with unchanged draft candidates. Falsification: another full-sized draft gather, BSS not enabled, bytes not matching ownership/rows, or no reduction in target communication time once rank skew is included. For future sampler design, reject it if local selection/rejection overhead consumes the savings, seeded greedy outputs differ, or sampling/logprob/acceptance checks fail. Do not infer a speedup from fewer NCCL calls alone.

Offline validation: `bash deliver/verify-0143.sh` copies the original tree, dry-runs and applies at fuzz zero with real status checking, compiles all seven touched Python files, and runs five standard-library tests (strict grammar, no-op metadata behavior/scoped tags, byte math, collective coverage, synthetic trace correlation). **PASS**. Build, actual head-sharing branch, profiler capture/replay correlation, enabled startup under torch compilation, CUDA/NCCL behavior, numerics and timing remain unverified on hardware.
