## Why (measured, R184, 2026-09-04)

The served daily is vLLM 0.29.0rc2 + FlashInfer 0.6.16.post3 + torch 2.13.0+cu130 (`s-image/VERSIONS`), TP=2 on two RTX 5090 (sm_120, PCIe Gen5 x8, no NVLink, no P2P over NVLink; `CustomAllreduce` reports `full_nvlink: None`). The decode step's largest two-card cost is vLLM's custom all-reduce: 15% of the step at 1 stream, 27% at 8, 33% at 16 (R183 profile). R184 (`run-bench.log`, run of 21:42 UTC) measured the three kernels in CUDA graphs, µs per call, bf16 rows × 5,120:

| rows | NCCL | vLLM CustomAllreduce | FlashInfer pcie_ipc |
|---|---|---|---|
| 1 | 13.7 | 4.9 | 1.9 |
| 10 (1 stream, 9-token draft) | 17.5 | 8.8 | 5.6 |
| 80 (8 streams) | 46.0 | 49.0 | 33.5 |
| 160 (16 streams) | 80.4 | 86.0 | 65.3 |
| 320 | 149.5 | 160.1 | 129.0 |
| 2,048 | 899.9 | 960.6 | 817.9 |

All cells exact vs the NCCL reference, eager and after graph replay. Expected gain on the daily ≈ 8% of the decode step at 8 and 16 streams. That is the target of this brief.

## Constraints

1. FlashInfer 0.6.16.post3 stays the installed package. Its attention path is what the daily's fidelity work (R168) depends on; swapping the whole library to main is out. The pcie_ipc kernel must therefore come in as a vendored, separately named package (e.g. `pcie_ipc_ar/` under dist-packages, or under `vllm_sm12x/`), with its CUDA sources and whatever JIT/autotune glue it needs, without shadowing `flashinfer.*`.
2. Codex has no GPU. The kernel is JIT-compiled by main's `flashinfer.jit` machinery at first use; the deliverable must either (a) reuse 0.6.16's `flashinfer.jit.core` (`gen_jit_spec`, `JitSpec`) and `flashinfer.autotuner` if they are API-compatible with what `pcie_ipc_ar.py`/`jit/comm.py` need — check line by line and say which symbols differ — or (b) carry a minimal copy of main's `jit/core.py` + `autotuner/` under the vendored name (state the size of that copy), or (c) build the `.so` with `torch.utils.cpp_extension` / plain nvcc at image build time from the vendored `csrc` + `include` (nvcc is in the image; the `-gencode` for sm_120 is `arch=compute_120a,code=sm_120a` in this image's other JIT modules — check `BUILT_CACHE_LISTING` and `jit/comm.py` for the flags main used) and load it with `torch.ops.load_library`. Prefer the smallest option that you can show compiles conceptually; explain why. A build-time compile (c) is welcome because it makes the boot deterministic; if you pick (c) also keep a lazy fallback.
3. Tuning: the served path must not run the autotuner at every boot. Ship `pcie-tune-free.json` as the fixed config and load it (the class supports `tune_cache`; `tune()` may still be needed to populate the in-process cache from the file — read how `tuned_launch_config`/`_resolve_tuned` consult the cache and whether `prepare()` alone suffices with a cache file). Every rank must resolve the same configs.
4. Graph capture: `prepare()` must be called with every shape that will be captured, BEFORE capture, AFTER `tune()`; a shape first seen inside a capture raises (`tuned_launch_config`). The shapes are (capture_size, 5120) bf16 for the target's FULL and PIECEWISE graphs (sizes from `r182-compilation-config.txt`, padded — check `model_runner.py`/`cudagraph_dispatcher.py` for how the token count is padded to a capture size and whether the all-reduce sees `(num_tokens, hidden)` or `(num_tokens*?, hidden)`), plus the drafter's captured shapes (`dflash/cudagraph.py`, `speculator.py`: what batch sizes it captures and what the hidden size of its all-reduce is — the drafter is a DFlash2 model with its own hidden size; find it or make the prepare list configurable). Any shape not in the resolved set must fall back to `CustomAllreduce` (which works inside capture via its own `capture()` registration) — never raise inside capture. Also: eager (prefill) shapes are resolved lazily, which is a collective with a host read-back — that is allowed outside capture, but state the cost and whether a size cap (e.g. only rows ≤ 320 or bytes ≤ 8 MiB go to pcie_ipc, larger to NCCL as today) is the better contract. R184 says pcie_ipc wins at every size, but the served contract must stay safe.
5. One workspace serves one stream (`_check_stream`, `rebind_stream`). Find every stream vLLM's TP all-reduce can run on in this image (forward stream, the drafter's stream if it has one, profiling/dummy runs, `graph_capture()` side stream — `parallel_state.graph_capture` uses a dedicated capture stream; capture is exempt but the warm-up before capture is not; also async scheduling / `cudagraph_num_of_warmups 1`). Decide: one workspace bound at first use with `rebind_stream()` after a synchronize when the stream changes, or a workspace per stream. Never a hang.
6. Dispatch order in `CudaCommunicator.all_reduce` (`cuda_communicator.py`): insert the pcie_ipc path ahead of `CustomAllreduce`, only for `dtype == bf16`, only when `supports()` is true and the shape is resolved (or we are not capturing), guarded by an env knob `VLLM_SM12X_PCIE_IPC_AR=1` (off by default, read via `os.environ` at communicator init the way `envs.py` does for other knobs; do not add to `envs.py` unless trivial). With the knob off the image must behave bit-identically to today. Keep `disable_custom_all_reduce` semantics untouched. World size 2 only (assert and fall back otherwise).
7. Memory: `max_numel` sizes the IPC workspace. Compute what the workspace allocates per rank for `max_numel = 320*5120` vs `8192*5120` (read the allocation in `pcie_ipc_ar.py`/`.cuh`); the daily runs at a 13.98 GB KV pin with ~1.8 GiB free after capture, so the workspace must be small and allocated BEFORE `determine_available_memory` profiles (find where the communicator is constructed relative to profiling in `gpu_worker.py`/`model_runner.py`; `CustomAllreduce` allocates its buffers at init, do the same). State the bytes.
8. Correctness: bf16 rows × 5120; the 2-rank sum is order-independent, so results are exact vs NCCL (R184 confirmed). Nothing to adjudicate numerically, but say whether the kernel has any alignment/size constraints (`supports()`), and what happens at 1 row.
9. The patch must apply with `patch --batch --forward -p1 --fuzz=0` on top of the dumped files (which already carry 0132–0137). Keep it surgical: one new communicator module (e.g. `vllm/distributed/device_communicators/pcie_ipc_all_reduce.py`, modelled on `flashinfer_all_reduce.py`/`symm_mem.py`), the dispatch hook in `cuda_communicator.py`, the prepare hook at the right point before capture (`model_runner.capture_model` or `parallel_state.graph_capture`), and the drafter's shapes.
