# Gotchas

Failure modes found on this stack, current generation first. Each entry says what breaks, how it was detected, and what the launcher does about it. Flag rationale is in [CONFIG.md](CONFIG.md); rejected configurations are in [REJECTED.md](REJECTED.md).

## Correctness

1. **The NVFP4 store overlay is required on `sm_120` and its absence is invisible to behavioural tests.** vLLM's in-tree writer swizzles V block scales for SM100; the FA2 and XQA readers on sm120 address them linearly. With the stock writer the engine is fluent, passes needles to 100K and a full tool-eval, and has 2.7 to 10 times the attention error (relative L2 0.335 to 1.30 versus 0.124). Only [`patches-v0280/overlay/diag_vsf_layout.py`](../patches-v0280/overlay/diag_vsf_layout.py) catches it. The launcher refuses to serve without the overlay's ACTIVE line in the boot log. Re-run the diagnostic after any vLLM bump that touches `nvfp4_kv_cache_kernels.cu`.
2. **Prefill-only fidelity probes cannot see decode kernels.** `prompt_logprobs` never executes a decode step, so a broken decode kernel (XQA, for example) reads bit-identical on a prefill ruler. Validate decode-path changes with [`scripts/decode_fidelity.py`](../scripts/decode_fidelity.py) plus a task-accuracy A/B.
3. **Test a KV tier with a needle retrieved after a restart.** Coherent output and rising hit counters were compatible with a broken tier through four rounds in 2026-07 ([archive/LMCACHE.md](archive/LMCACHE.md)). A needle planted deep in a long context, retrieved after `docker restart`, is the first gate of every audition.
4. **The tier namespace comes from the mount path, not the weights.** vLLM's fs offload tier names its namespace from `model_name` (the mount path), dtype and parallelism. Swapping checkpoints under the same mount serves the previous checkpoint's KV blocks on every revisit. The launcher stamps the tier with the checkpoint name and wipes all namespaces when it changes.
5. **DFlash2 drafts read the target's KV non-causally.** That is a third read path beyond XQA decode and FA2 causal prefill, and on NVFP4 pages at TP=2 it still carries an open correctness bug. The two-card configuration pairs DFlash2 with fp8 KV; the NVFP4 candidate disables XQA and keeps the prefill chunk at 8192 ([`scripts/serve-nvfp4-candidate.sh`](../scripts/serve-nvfp4-candidate.sh)).
6. **Verify the engine, not the launcher banner.** After every launch check the image, `vllm.__version__`, the overlay line, `decode_backend=xqa` (one card) and the pool inside its band. In 2026-08 a stale exported variable ran an old image under a new banner for six days.
7. **Check `tokenizer.json` for a baked truncation.** One checkpoint shipped `"truncation": {"max_length": 8192}` from calibration. Text worked; multimodal requests past 8192 tokens returned HTTP 400. The launcher nulls it at every boot because a re-download reinstates it.

## Performance measurement

8. **Never pass `--no-async-scheduling` on vLLM 0.28 or later.** It guarded a 0.26-era scheduler bug and now disables a default optimization: dropping it measured +21% prose and +29% code single-stream decode.
9. **Single-stream decode with speculative decoding varies about 10% between boots** on identical prompts (acceptance 0.43 to 0.69). T=0 outputs are bit-identical across boots, so the mechanism is sampling divergence through content-dependent acceptance. Compare within one boot, normalize by accepted tokens per step, or probe at T=0.
10. **The KV pool varies between boots.** On the two-card shape the profiler's activation estimate is bimodal and the pool lands at 654,491 or 628,798. Use bands, not exact values.
11. **Draft acceptance measures drafter-target agreement, not quality.** A quantized drafter beat the bf16 original on two checkpoints here; a mid-fidelity QAT checkpoint lost 26% code decode to drafter mismatch. Re-run the drafter A/B for every checkpoint change.
12. **Deep-context TTFT can be warm-inflated by the tier.** A 200K prefill on a corpus the tier had already stored read 28% faster than cold. Check the 200K to 100K TTFT ratio (about 3.5 cold on this hardware) before comparing across boots.
13. **Reasoning models starve `content` on small `max_tokens`.** A 64-token probe returns empty content because the budget goes to reasoning. Score content or reasoning, and budget 400 or more tokens in probes.
14. **`prefix_cache_hits_total` reads 0 with an external connector on.** Time a repeated prompt instead ([`bench/prefix_probe.py`](../bench/prefix_probe.py)).
15. **Admission on the two-card shape is bounded by the pool, not by `--max-num-seqs`.** Each request holds at least one block in every KV group and the mamba page carries the speculative state slots; about 17 short requests fit. Above that, requests wait on capacity and deep contexts cause preemption storms instead of queueing (`results/2026-09-02-r159-conc-b`).

16. **A per-image pixel cap can OOM the engine at serve time.** `--mm-processor-kwargs max_pixels` makes the boot profiler encode many small images instead of one 16,384-token image; the activation reserve shrinks, the KV pool grows 13K tokens, and the FlashInfer autotuner then fails to allocate during the first deep batch (240 MiB needed, 197 MiB free at util 0.92). Raising the image count alone does not change the profile.

## Host and operations

17. **The offloading connector leaks its staging mmap past `docker rm -f`** (`/dev/shm/vllm_offload_*.mmap`, 4 GiB each). Four engine swaps ate 16 GiB of host RAM. The launcher sweeps orphans before every boot.
18. **Engine swaps can transiently exceed host RAM.** `docker rm -f` returns before the old engine's memory is reaped; booting the next engine into that window drove the host into hours of thrash. The launcher waits for enough available memory before starting the container, the engine runs with a memory cap, and [`scripts/setup-earlyoom.sh`](../scripts/setup-earlyoom.sh) kills the largest client process before the kernel OOM killer runs.
19. **The disk tier has no eviction and no enforced capacity.** vLLM's fs tier fills to 100%, then new stores fail per job while reads keep hitting; at boot a full tier crashes engine init. The tier lives on a fixed-size loopback filesystem so the root disk is never at risk, the launcher refuses to boot with under 5 GB free, and [`scripts/tier-evict.sh`](../scripts/tier-evict.sh) evicts on a timer. An earlier generation's cache once grew to 876 GB past a 60 GB configured cap.
20. **Loopback tiers double-cache unless the loop device uses direct I/O.** A buffered loop device holds the tier's pages in the page cache a second time; under an evaluation load that consumed 37 GB of host memory. Re-attach with `losetup --sector-size 4096 --direct-io=on` (plain `--direct-io=on` silently no-ops on 512-byte-sector devices).
21. **A TP=2 boot right after a GPU teardown can hang.** One worker dies with `CUDA error: invalid argument` during kernel warmup and the other waits forever. Seen once, in the first hour after a kernel-panic reboot, with 45 second settles; a 300 second settle booted first try. On a healthy box 60, 120 and 180 second settles all boot first try (bench/RESULTS.md, settle ladder), so the scripts settle 60 seconds and fall back to 300 only after a failed boot. The launcher aborts within seconds on the worker error instead of waiting out the health timeout.
22. **NVMe device names can swap across reboots.** Resolve mounts through `findmnt`, never by `/dev/nvmeXn1`.
23. **Never `kill -SIG -<pgid>` with procps `kill`.** It parses the negative group ID as `kill(-1)` and signals every process. That took the host offline for five days in 2026-08. Use the bash builtin with `--`, or systemd units.
24. **Never set `PYTORCH_ALLOC_CONF=expandable_segments` with a KV connector.** Expandable segments are not CUDA-IPC-exportable and `register_kv_caches` times out after 300 s with no useful error.

## Harnesses

25. **A harness may silently disable function calling for an unknown model name.** R2E-Gym's local patch enabled OpenAI function calling only for model names matching a pattern; serving under a new name turned it off (step-0 prompt 943 versus 2,519 tokens, 5/25 instead of 20/25). Check the step-0 prompt size before trusting an agentic run.
26. **Assistant turns with `content: null` are rejected on resend.** Tool-call-only or reasoning-only turns, which Qwen3.8 produces often, return HTTP 400 when a harness resends them verbatim. Send an empty string instead.
27. **Anonymous Docker Hub pulls are limited to 100 per hour per IP.** SWE-Bench scoring pulls one image per instance; the first official pass once showed 27/500 because of pull errors. Use a pull-through mirror such as `mirror.gcr.io`, or authenticate.
